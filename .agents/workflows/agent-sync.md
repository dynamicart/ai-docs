Read the contents of the `_docs/` folder and regenerate the `agent.md` file in the project root.

## Division of responsibility (read this first)

`agent.md` is **not** a status report — that's what `_docs/PROJECT-OVERVIEW.md` is for
(regenerated by `/project-sync`). `agent.md` is the *stable, agent-facing* digest: what an
agent needs to know before touching this codebase at all, plus a **map** telling it exactly
which `_docs` file to open for anything dynamic (active tasks, decisions, journals). Never
copy dynamic/status content into `agent.md` that already has a canonical home elsewhere in
`_docs` (`tasks/index.md`, `journal/index.md`, `DECISIONS-LOG.md`) — link to it instead. This
keeps `agent.md` cheap to keep in context every session and avoids drift between two copies of
the same fact.

## Source files (read in order):

1. **_docs/_templates/AGENT-template.md** — Preserving the basic structure and manual sections.
2. **_docs/index.md** — OKF bundle root index; sanity-check that the `@_docs/index.md` import
   and the "Where things live" pointers below stay valid (nothing listed there is missing, no
   dead links).
3. **_docs/arch/*.md** and **_docs/spec/*.md** — Architectural and business context, and the
   basis for the "Where things live" directory map.
4. **_docs/PROJECT-OVERVIEW.md** — Project description and tech stack basis: read only its
   *stable* parts (frontmatter `project`/`description`/`stack`, "What is it for?", "Technical
   stack"), never its status sections.
5. **README.md** (repo root) — Secondary source for the description, but only if it describes
   this project: skip it while it is still the AI Docs template placeholder ("Project Name").

`_docs/README.md` describes the documentation system itself, not the project. Never use it as the
project description. If neither 4 nor 5 describes the project yet (fresh project from the
template), don't generate `agent.md` from framework files: stop and tell the user to run
`/project-sync` first (its first run collects the project's identity), then `/agent-sync` again.

Note: `/agent-sync` never writes to `_docs/index.md` or `_docs/log.md` — those are maintained by
`/task-new`, `/task-close`, `/journal-distill`, and `/project-sync`. It only reads them. It also
does not read `_docs/tasks/*.md`, `_docs/journal/*.md`, or `_docs/DECISIONS-LOG.md` for content
to copy — those stay pointers only (see Generation Rules).

## Generation Rules:

1. **Boundaries:** Always respect the `<!-- AGENT_SYNC_BOUNDARY -->` marker. Only overwrite the part above it!
2. **About the Project:** Summarize the essence based on `PROJECT-OVERVIEW.md`'s stable parts, the root `README.md` (if it describes this project) and `arch/`/`spec/` files (2-3 sentences).
3. **Tech Stack:** Collect technologies (source: `arch/STACK.md` if present, otherwise `PROJECT-OVERVIEW.md`'s stack).
4. **Where things live:** A short, stable directory map (source: `arch/DIRECTORY-MAP.md` if
   present, otherwise the real top-level folder structure) — enough for an agent to orient
   without exploring the tree.
5. **What you need to know before working:** Stable conventions/rules (coding style,
   documentation rules, manual-test policy, OS quirks, etc.) — unchanged in spirit from before.
   Include the generated-file rules (`BOARD.md`/`index.md`/`log.md` are never hand-edited) and the
   `_docs/modules/*.md` manual-only, human-approved rule — these are stable conventions, not status,
   so they belong here rather than behind the import.
6. **Where to look for more:** Always end the generated part with an `@_docs/index.md` import
   (Claude Code's native `@import` syntax) so the full `_docs` map — tasks, journals, decisions,
   arch, spec — is pulled in automatically every session, at near-zero token cost, instead of
   being copied and re-summarized here. Do not also inline Active Tasks / Recent Journals / Key
   Decisions / Open Questions sections — those are `/project-sync`'s job.

## /agent-sync command execution:

- Do not ask back.
- Find or create `agent.md` in the root.
- If it already exists, preserve the manual part below the boundary.
- Output: "`agent.md` successfully updated."

## AGENT.MD SIZE LIMITS

`agent.md` should remain under ~80 lines for efficient readability — it now holds only stable,
rarely-changing facts plus one map import, so it should rarely need to grow.
