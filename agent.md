## About the Project

AI Docs is a Markdown-based framework for AI-driven documentation workflow automation:
TASK/JOURNAL/ADR management through `/` commands, a plaintext kanban, and an OKF v0.2-conformant
`_docs/` knowledge bundle that acts as a cross-agent "Shared Brain". The repository is both the
template and its first application — it ships the standalone, server-less HTML/JS **Docs & Board
Viewer** (`tool/docs-viewer.html`), which loads a `_docs/` folder and renders kanban, reader and
search views without Obsidian.

## Tech Stack

- **Docs:** Markdown + YAML frontmatter (OKF v0.2), `_docs/` doubles as an Obsidian vault
- **Tooling:** Vanilla HTML5/JS (inline CSS/JS, no build, no external deps)
- **Agents:** Antigravity, Claude Code, OpenCode — workflows as `/` commands in `.agents/workflows/`
- **Other:** Git, `.agents/skills/` + `.agents/rules/style-guide.md`

## What you need to know before working

- Full development documentation lives in the `_docs/` folder.
- **Documentation first (Zero blind probing):** Never probe the environment via shell commands (e.g. `php -v`, `node -v`) or spawn exploratory subagents before consulting the Tech Stack section above and `_docs/arch/` (e.g. `STACK.md`). The tech stack and invariants are documented; only run discovery commands if the information is missing from the docs.
- `_docs/` is an OKF v0.2 bundle: every TASK/JOURNAL/ADR/MODULE is a concept with a `type`
  frontmatter field; use bundle-relative links (`/tasks/...`), never `[[wikilinks]]`.
- **Generated — never hand-edit:** `_docs/BOARD.md` (`/board-sync`), `_docs/index.md` and
  `_docs/PROJECT-OVERVIEW.md` (`/project-sync`), and this file above the boundary (`/agent-sync`).
  To change board state, check off an item in the TASK file's "Approach / Plan" list instead.
- `_docs/modules/*.md` are durable references, created and updated **only** through a manual,
  human-approved `/module-sync` run — no other workflow may touch them.
- `_docs/log.md` is append-only; it is written by `/task-new`, `/task-close`, `/journal-distill`
  and `/arch-sync`, and never rewritten retroactively.
- Record every major decision in the TASK file, or as an ADR in `_docs/DECISIONS-LOG.md`.
- Every workflow file in `.agents/workflows/` is a `/`-command definition: read it and execute it
  as written, and never invoke one the user didn't ask for.
- Always run `/task-close` upon task completion; see `.agents/rules/style-guide.md` §5 for the rest
  of the end-of-task maintenance routine.
